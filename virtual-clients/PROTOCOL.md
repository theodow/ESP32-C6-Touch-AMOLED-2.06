# Πρωτόκολλο MQTT Fall Guardian, έκδοση 1

Το ίδιο πρωτόκολλο μιλούν τα πραγματικά ρολόγια (firmware ESP32-C6) και τα
virtual clients του simulator. Ένας server ή ένα dashboard δεν χρειάζεται να
ξέρει ποιο είναι ποιο, εκτός αν το θέλει (πεδίο `virtual` στο `status`).

## Topics

Όλα τα topics είναι κάτω από `fallguardian/v1/<device_id>/`. Το `device_id`
δεν περιέχει `/`, `+` ή `#`. Για το πραγματικό ρολόι προτείνεται
`fg-<MAC χωρίς άνω-κάτω τελείες>`, για τα virtual `vw-0000`, `vw-0001`, …

| Topic (μετά το `<device_id>/`) | Κατεύθυνση | QoS | Retain | Πότε |
|---|---|---|---|---|
| `status` | ρολόι → server | 1 | ναι | στη σύνδεση, στο `ping`, και ως LWT (`online:false`) |
| `telemetry` | ρολόι → server | 0 | όχι | περιοδικά (προεπιλογή κάθε 5 s) |
| `event/fall` | ρολόι → server | 1 | όχι | όταν ο ανιχνευτής στο ρολόι αποφασίσει πτώση |
| `event/cancel` | ρολόι → server | 1 | όχι | ο χρήστης πάτησε «Είμαι καλά» |
| `imu` | ρολόι → server | 0 | όχι | προαιρετικά, ακατέργαστα δείγματα σε παρτίδες |
| `cmd` | server → ρολόι | 1 | όχι | επιβεβαίωση συναγερμού, ρυθμίσεις, ping |
| `sim/truth` | simulator → server | 1 | όχι | μόνο virtual: πραγματική ετικέτα κάθε εγγραφής |

Ένας server εγγράφεται στο `fallguardian/v1/+/#`. Ένα ρολόι εγγράφεται μόνο στο
δικό του `fallguardian/v1/<device_id>/cmd`.

## Κοινά πεδία

Κάθε payload είναι αντικείμενο JSON σε UTF-8 με:

- `v`: έκδοση πρωτοκόλλου (ακέραιος, τώρα `1`).
- `ts`: χρόνος σε ms από το Unix epoch, από το ρολόι του device (SNTP/RTC).

Προαιρετικά πεδία που δεν έχουν τιμή παραλείπονται, δεν στέλνονται ως `null`.
Μονάδες: επιτάχυνση σε g, γυροσκόπιο σε °/s (ό,τι δίνει ο QMI8658).

## Μηνύματα

### `status`
```json
{"v":1,"ts":1792356000000,"online":true,"fw":"fallsim-0.1","model":"threshold-v1","fs":50,"virtual":true}
```
Το LWT που δηλώνεται στη σύνδεση είναι `{"v":1,"ts":…,"online":false}` με retain,
ώστε ο server να μαθαίνει αμέσως ποια ρολόγια χάθηκαν. Σε κανονικό κλείσιμο
το ρολόι στέλνει το ίδιο μήνυμα πριν το disconnect.

### `telemetry`
```json
{"v":1,"ts":1792356005000,"battery_pct":87.4,"rssi_dbm":-61,"uptime_s":3605,
 "acc_mag_mean":1.003,"acc_mag_max":1.412,"acc_mag_std":0.081,"activity":"idle"}
```
Τα `acc_mag_*` είναι στατιστικά του μέτρου της επιτάχυνσης από το προηγούμενο
μήνυμα telemetry. Τα virtual προσθέτουν και ένα μπλοκ `sim` με την εγγραφή
που παίζει εκείνη τη στιγμή.

### `event/fall`
```json
{"v":1,"ts":1792356012340,"event_id":"3f9a1c0b7e21","confidence":0.874,
 "detector":"threshold-v1","peak_g":4.12}
```
`event_id` μοναδικό ανά συμβάν (12 hex). `detector` λέει ποιος ανιχνευτής
αποφάσισε (`threshold-v1` σήμερα, όνομα/έκδοση μοντέλου TinyML αργότερα), ώστε
να συγκρίνονται μοντέλα στο ίδιο stream.

### `event/cancel`
```json
{"v":1,"ts":1792356020000,"event_id":"3f9a1c0b7e21","reason":"user_ok"}
```

### `imu`
```json
{"v":1,"ts":1792356000000,"seq":42,"fs":50,
 "acc":[[0.01,-0.02,0.99],[0.02,-0.01,1.01]],"gyr":[[0.5,1.2,-0.3],[0.4,1.1,-0.2]]}
```
`ts` είναι ο χρόνος του πρώτου δείγματος, το δείγμα `k` είναι στο
`ts + k*1000/fs`. `seq` αυξάνεται κατά 1 ανά παρτίδα ώστε να φαίνονται οι
απώλειες (QoS 0). Είναι κλειστό εκ προεπιλογής και ανοίγει με `cmd config`:
χρησιμεύει για καταγραφή δεδομένων και για inference στον server.

### `cmd`
```json
{"v":1,"ts":…,"cmd":"ack","event_id":"3f9a1c0b7e21"}
{"v":1,"ts":…,"cmd":"config","telemetry_interval_s":10,"imu_stream":true}
{"v":1,"ts":…,"cmd":"ping"}
```
- `ack`: κάποιος (φροντιστής/server) είδε τον συναγερμό. Το ρολόι μπορεί να το δείξει στην οθόνη.
- `config`: αλλάζει ρυθμίσεις. Άγνωστα κλειδιά αγνοούνται.
- `ping`: το ρολόι ξαναστέλνει `status`.

### `sim/truth` (μόνο virtual)
```json
{"v":1,"ts":…,"recording":"F05_SA01_R01","activity":"F05","is_fall":true,
 "detected":true,"start_ts":…,"end_ts":…,"event_ids":["3f9a1c0b7e21"]}
```
Στέλνεται λίγο μετά το τέλος κάθε εγγραφής (3 s περιθώριο, γιατί ο ανιχνευτής
αποφασίζει αφού ηρεμήσει το σήμα). Ο monitor φτιάχνει από αυτά πίνακα
σύγχυσης, ευαισθησία και ειδικότητα ανά δραστηριότητα. Τα πραγματικά ρολόγια
δεν το στέλνουν ποτέ.

## Γιατί έτσι

- **Topic ανά device**: ACL στον broker ανά ρολόι (`fallguardian/v1/<id>/#`), και
  ένα wildcard subscription για τον server.
- **QoS 1 για ό,τι είναι συναγερμός**, QoS 0 για ό,τι επαναλαμβάνεται. Η
  τηλεμετρία που χάνεται αντικαθίσταται από την επόμενη.
- **Retained `status` + LWT**: ο server ξέρει ποιος είναι online χωρίς polling,
  ακόμα κι αν ξεκινήσει μετά τα ρολόγια.
- **Ανίχνευση στο ρολόι**: το `event/fall` δεν εξαρτάται από το stream IMU, άρα
  δουλεύει και χωρίς σταθερό WiFi bandwidth. Το `imu` είναι εργαλείο έρευνας.
- **JSON**: διαβάζεται εύκολα και αρκεί για 50 Hz. Αν χρειαστεί μικρότερο
  payload στο ESP32-C6, το `imu` μπορεί να γίνει CBOR σε `v2` χωρίς αλλαγή στα υπόλοιπα.
